# ml_tagger — ตัวติดป้ายตัวเลข (เดโม Phase 2, สถานะ: ทดลอง)

โมเดลเล็ก (~257,000 พารามิเตอร์, ไฟล์ ONNX ~1 MB) ที่ดูทีละตัวอักษรของโน้ต แล้วบอกว่า **ตัวเลขแต่ละตัวเป็นพารามิเตอร์อะไร**
(FBS, HbA1c, BP, HomeBP, BW, BMI, Creatinine, eGFR หรือไม่ใช่ค่าแล็บ เช่น วันที่/อายุ)
ใช้ช่วย **อ่าน** ชื่อที่ parser เดิมไม่รู้จัก ไม่ได้ตัดสินกฎทางคลินิก ต่อเข้าเว็บเป็นตัวเลือก `python3 -m server.app --tagger` (หมอต้องกดยืนยันทุกข้อ ดู README หลัก)

## ผลที่วัดแล้ว = ข้อมูลสังเคราะห์เท่านั้น (ไม่ใช่โน้ตจริง)
| ชุดทดสอบ | tagger | parser เดิม |
|---|---|---|
| ชื่อที่เคยเห็นตอนฝึก | 100% | 86% |
| ชื่อที่ไม่เคยเห็น | 86% (94.7% เมื่อรับเฉพาะความมั่นใจ >= 0.95, ครอบคลุม 76%) | 17% |

ตัวเลขเหล่านี้เกินจริงโดยธรรมชาติ (ตัวสร้างข้อมูลเขียนโดยคนเดียวกับที่ตั้งชื่อ) ความถูกต้องกับโน้ตจริงยัง **ไม่ทราบ**
ความเร็ว: Mac 0.7 ms/โน้ต · RDK X5 32 ms/โน้ต (CPU 1 เธรด) · RAM น้อยกว่า 100 MB

## วัดกับโน้ตจริงบนเครื่อง รพ. (ไม่ใช้เครือข่าย, ไม่ต้อง torch)
```
cd ml_tagger/real_eval
pip install onnxruntime numpy
python3 eval_real.py scan  โฟลเดอร์โน้ต/        # 1 ไฟล์ .txt = 1 โน้ต (หรือ .jsonl / ไฟล์เดียวคั่นด้วย ---)
python3 eval_real.py review                       # หมอดูทีละตัวเลข Enter=ถูก, พิมพ์เลขคลาสที่ถูก
python3 eval_real.py score                        # ความถูกต้อง + ช่วงเชื่อมั่น
```
- ผลลัพธ์อยู่ใน `real_eval_out/` (ไม่เก็บข้อความโน้ต เก็บตำแหน่ง/คลาส/ความมั่นใจ) **ยังเป็นข้อมูลที่เกี่ยวกับผู้ป่วย ห้ามส่งขึ้นเน็ตหรือ commit** (`.gitignore` กันไว้แล้ว)
- ใช้โน้ตที่ถอดข้อมูลระบุตัวตนแล้ว และขออนุญาต IT/DPO ก่อน ตรวจอย่างน้อย 100 ตัวอย่างสุ่ม
- ตัวชี้วัดหลัก = "ตัวอย่างสุ่ม" ส่วนกลุ่มที่ parser เดิมไม่เห็นด้วยถูกเลือกมาเพราะสงสัย จึงไม่ใช่ค่าเฉลี่ย

## ฝึกใหม่ (ต้องมี torch; ข้อมูลสังเคราะห์ล้วน)
`pip install torch numpy onnx onnxruntime onnxscript` แล้ว `python3 train.py` (~13 นาทีบน Mac) ได้ `tagger.onnx` + `tagger_meta.json`

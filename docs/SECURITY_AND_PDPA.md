# ความปลอดภัยและ PDPA: อะไรรับประกันได้ อะไรยังไม่ได้

> ไม่ใช่คำปรึกษากฎหมาย การใช้ข้อมูลผู้ป่วยจริงต้องผ่านผู้รับผิดชอบข้อมูลของ รพ. (DPO / กรรมการจริยธรรม / ฝ่าย IT)

## ที่ระบบทำและ **มีการทดสอบอัตโนมัติพิสูจน์**

|---|---|

## ที่ระบบ **ไม่ได้** ทำ / ต้องทำเองก่อนใช้จริง
- **ยังไม่ผ่านการตรวจทางคลินิก** เกณฑ์และถ้อยคำเป็นค่าตั้งต้น (ดู `docs/RULES_REVIEW.md`)
- **ข้อมูลอยู่ในหน่วยความจำของโปรเซส** ชั่วคราวขณะประมวลผล (ไม่มี swap บนเครื่องที่ตรวจ แต่เครื่องที่ใช้งานจริงต้องตรวจเอง: swap/ไฟล์ hibernate/core dump อาจเขียนหน่วยความจำลงดิสก์)
- **เบราว์เซอร์** เก็บข้อความที่พิมพ์ในหน้าไว้จนปิด/ล้าง และการพิมพ์ใบให้ผู้ป่วยทำให้ข้อมูลออกสู่กระดาษ/คิวพิมพ์ของระบบ ปิดหน้าหลังใช้ และตรวจนโยบายเครื่องพิมพ์
- **ไม่มี HTTPS** ถ้าเปิดให้เครื่องอื่นเข้า (`--host`) ข้อมูลจะวิ่งแบบไม่เข้ารหัส ใช้เฉพาะ `127.0.0.1` หรือวางหลังพร็อกซี HTTPS ที่ IT ดูแล
- **ดิสก์ไม่ได้เข้ารหัส** (ฐานข้อมูลผู้ใช้เป็นไฟล์ `data/app.db` สิทธิ์ 600) เปิดการเข้ารหัสดิสก์ของเครื่อง (FileVault/BitLocker/LUKS)
- **บัญชีผู้ใช้ไม่มี 2 ขั้นตอน** PIN เป็นการป้องกันระดับกันคนผ่านหน้าจอ ไม่ใช่ระบบยืนยันตัวตนระดับ รพ.
- **ผู้ที่เข้าถึงเครื่องระดับผู้ดูแลระบบ** ย่อมอ่านหน่วยความจำ/ดักแป้นพิมพ์ได้ ซอฟต์แวร์ป้องกันไม่ได้
- **ยังไม่ได้ทดสอบบน Windows**

## ก่อนนำข้อมูลผู้ป่วยจริงมาเทรน/ปรับพจนานุกรม
ได้รับอนุมัติ → ถอดเอกลักษณ์ (ชื่อ, HN, เลขบัตร, เบอร์โทร, วันเกิด, วันที่ที่ระบุตัวบุคคลได้) → ทำงานในเครื่องที่ รพ. กำหนดเท่านั้น → เครื่องมือใน `tools/` และ `eval/` ออกแบบไม่พิมพ์เนื้อหาบันทึก และแสดงเฉพาะวลีที่พบซ้ำหลายบันทึก **อย่าวางบันทึกจริงลงในแชทกับโมเดลบนคลาวด์ (รวมถึง Claude) ทุกกรณี**

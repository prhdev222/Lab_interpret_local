# Lab Interpreter (local) — ระยะ 0

แปลผลจากบันทึก OPD แบบย่อของแพทย์เจ้าของเครื่อง เป็นข้อความอธิบายผู้ป่วย **ด้วยระบบกฎ ไม่ใช้ LLM ไม่ใช้อินเทอร์เน็ต ไม่เก็บข้อมูลผู้ป่วย**
สร้างต่อยอดจากหน้าเว็บและขั้นตอน "ฉบับร่าง → ผู้ตรวจยืนยัน → พิมพ์" ของรีโป `prhdev222/Lab_interpret` (สำเนาต้นฉบับอยู่ใน `upstream/`)

> **สถานะ: ฉบับร่าง ยังไม่ผ่านการตรวจทานโดยแพทย์** — ห้ามใช้กับผู้ป่วยจริงจนกว่าจะตรวจ `docs/RULES_REVIEW.md` ครบและรับรอง

## ติดตั้งบนเครื่องใหม่ (deploy) และการเข้าสู่ระบบ — admin / password
ไม่ต้องล็อกอิน GitHub ถ้า repo เป็น public ส่วนตัวระบบเองใช้ **ชื่อผู้ใช้ + PIN ตัวเลข** (PIN คือ "password" ของระบบนี้) ไม่เกี่ยวกับบัญชี GitHub

1. ติดตั้ง Python 3.10 ขึ้นไป (ไม่ต้องติดตั้งไลบรารีเพิ่ม ไม่ต้องใช้อินเทอร์เน็ตตอนรัน)
2. `git clone https://github.com/prhdev222/Lab_interpret_local.git` แล้ว `cd Lab_interpret_local`
3. ตรวจว่าใช้ได้: `python3 -W ignore -m unittest discover -s tests -t .` (ต้องขึ้น OK)
4. `python3 -m server.app` — **ครั้งแรก** ระบบสร้างบัญชีผู้ดูแลและพิมพ์ออกหน้าจอ **ครั้งเดียว**:
   ```
   สร้างบัญชีผู้ดูแลครั้งแรก:  ชื่อผู้ใช้ admin   PIN 12345678
   ```
   **จด PIN นี้ทันที** ระบบเก็บเฉพาะค่าที่เข้ารหัส ดูย้อนหลังไม่ได้ (PIN แต่ละเครื่องสุ่มไม่เหมือนกัน)
5. เปิดเบราว์เซอร์ที่ `http://127.0.0.1:8741` ล็อกอินด้วย **ชื่อผู้ใช้ `admin`** และ **PIN ที่จดไว้**
6. เพิ่มผู้ใช้อื่น: ล็อกอินเป็น admin → ปุ่ม **👥 จัดการผู้ใช้** (ชื่อผู้ใช้ ชื่อแสดง PIN 6 หลักขึ้นไป ตำแหน่ง) หรือ `python3 manage.py add-user ชื่อ "ชื่อแสดง" doctor`
7. ลืม PIN: บนเครื่องนั้น รัน `python3 manage.py reset-pin admin` (ถามให้ตั้ง PIN ใหม่) ดูรายชื่อ: `python3 manage.py list-users`

หมายเหตุ: ใส่ PIN ผิด 5 ครั้งถูกล็อก 5 นาที · บัญชีอยู่ในไฟล์ `data/app.db` บนเครื่องนั้นเท่านั้น (ไม่ถูกส่งขึ้น GitHub) จึงควรสำรองไฟล์นี้เอง · ระบบเปิดให้เฉพาะเครื่องนั้น (127.0.0.1) ถ้าจะให้เครื่องอื่นเข้าถึงต้องให้ IT กำหนด และควรมี HTTPS ก่อน (ดู `docs/SECURITY_AND_PDPA.md`)

## รัน

```
python3 -m server.app                   # http://127.0.0.1:8741  (เครื่องนี้เท่านั้น; เปลี่ยนพอร์ตด้วย --port)
```
ครั้งแรกจะสร้างบัญชี `admin` พร้อม **PIN สุ่ม 8 หลัก แสดงครั้งเดียว** จดไว้ ลืมแล้วรีเซ็ตได้ด้วย `python3 manage.py reset-pin admin`
ต้องใช้ Python 3.10 ขึ้นไป ไม่ต้องติดตั้งไลบรารีเพิ่ม (ใช้เฉพาะของที่มากับ Python) ทดสอบแล้วบน macOS (Python 3.14) และ Linux ARM64 (Python 3.10, บอร์ด RDK X5 แรม 8 GB) **ยังไม่ได้ทดสอบบน Windows**

ทรัพยากรที่วัดจริงบน RDK X5 (Cortex-A55, ตัวเลขนี้คือเครื่องที่ช้าสุดที่มี): แรม **~22 MB** (ว่าง ~20 MB, สูงสุดหลังรับ 700 คำขอ 22 MB) · ตอบสนอง **มัธยฐาน 22 ms** (p95 29 ms) · ผู้ใช้ 8 คนพร้อมกัน 69 คำขอ/วินาที ไม่มีข้อผิดพลาด · ล็อกอิน ~0.66 วินาที (แฮช PIN แบบหนักโดยตั้งใจ บน PC ทั่วไปเร็วกว่านี้) ไม่ใช้ GPU ไม่ใช้อินเทอร์เน็ต ดังนั้นเครื่อง PC ของ รพ. ที่แรม 4-8 GB เหลือเฟือ

## รูปแบบบันทึกที่อ่านได้
ดู `docs/NOTE_FORMAT.md` สรุปคือ `ปัญหา : ค่า` (ซ้ายสุด = เก่าสุด ขวาสุด = ล่าสุด) และ `วัน/เดือน/ปี : ข้อความวันนี้` ระบบ **ไม่เดา** สิ่งที่ไม่เข้าใจจะแสดงให้ตรวจสอบ ค่าที่เป็นไปไม่ได้จะถูกข้ามและเตือน

## แก้กฎโดยไม่ต้องแก้โค้ด (ไฟล์ใน `data/`)
| ไฟล์ | คืออะไร |
|---|---|
| `lexicon.json` | พจนานุกรมคำย่อ ชื่อโรค อาการ (เพิ่มคำของคุณที่นี่) |
| `targets.json` | เกณฑ์/เป้าหมายทั้งหมด พร้อมช่องแหล่งอ้างอิง |
| `templates.json` | ถ้อยคำถึงผู้ป่วยและข้อสังเกตแพทย์ (ไม่มีตัวเลขเกณฑ์ฝังในข้อความ) |
| `glossary.json` | คำสามัญ ↔ คำสงฆ์ |

แก้แล้วรัน `python3 tools/dump_rules.py` (สร้างเอกสารตรวจกฎใหม่) และ `python3 -m unittest discover -s tests -t .` (ตรวจว่าไม่มีอะไรพัง)

## ให้ระบบ "เรียนรู้" ภาษาของคุณ (ไม่ต้องเทรน)
1. `tools/suggest_terms.py ไฟล์บันทึก.txt` — แสดงคำที่เจอบ่อยแต่ระบบยังไม่รู้จัก (แสดงเฉพาะคำที่พบ ≥ 5 บันทึก เพื่อไม่เผยข้อความที่เจอครั้งเดียว) แล้วเพิ่มลง `lexicon.json`
2. `eval/evaluate_parser.py --gold ไฟล์ของคุณ.jsonl` — วัดความแม่นรายช่อง (ไม่พิมพ์เนื้อหาบันทึก) ทำกับบันทึกจริงที่ถอดเอกลักษณ์แล้ว **ในเครื่องของคุณเท่านั้น**
3. `tools/synth_notes.py` — สร้างบันทึกสังเคราะห์สำหรับทดลอง (คะแนนบนข้อมูลนี้เป็นตัวเลขที่มองโลกในแง่ดี ไม่ใช่ความแม่นจริง)

## โครงสร้าง
```
engine/   parse_note.py (อ่านบันทึก) · rules.py (กฎ) · egfr.py · render.py (ข้อความ) · lexicon.py
server/   app.py (เว็บเซิร์ฟเวอร์) · db.py (ผู้ใช้/เซสชัน เท่านั้น)
public/   index.html (สร้างจาก upstream ด้วย tools/build_ui.py ทุกจุดที่แก้มีการตรวจว่าตรงพอดี)
data/     ไฟล์ที่แพทย์แก้ได้ (ตารางด้านบน)
tests/    ชุดทดสอบ  ·  docs/  เอกสารตรวจกฎ คู่มือรูปแบบบันทึก ความปลอดภัย/PDPA
```

ไฟล์ `data/app.db` เก็บบัญชีผู้ใช้ (ไม่มีข้อมูลผู้ป่วย) อย่าส่งต่อหรือนำขึ้นที่สาธารณะ

## ข้อจำกัดที่ต้องรู้
- ใช้ได้กับรูปแบบบันทึกของแพทย์เจ้าของเครื่อง หมอท่านอื่นที่เขียนต่างจะได้ "ไม่เข้าใจ" ไม่ใช่ผลผิด
- ครอบคลุม DM, HT, โรคอ้วน/น้ำหนัก, CKD, ไขมันในเลือด, ภาวะซีด/CBC, วาฟาริน/INR และบรรทัดวันนี้ (สูบบุหรี่ อาการ เลือดออก การรับประทาน) เท่านั้น ค่าอื่นอ่านได้แต่ยังไม่มีกฎ
- **ไม่มีการคำนวณ Thai CV risk score** (ยังหาสูตรต้นฉบับที่ตรวจสอบได้ไม่ได้ ดูหัวข้อในเอกสารตรวจกฎ)
- ระบบไม่วินิจฉัย ไม่สั่งยา ข้อความทุกประโยคมาจากแม่แบบที่แพทย์ตรวจ ผู้ตรวจต้องอ่านและยืนยันก่อนพิมพ์เสมอ
- ความแม่นของการอ่านบันทึกจริงยังไม่เคยวัด ต้องวัดด้วยบันทึกจริงที่ถอดเอกลักษณ์แล้ว


## แก้เกณฑ์และกฎจากหน้าเว็บ (เฉพาะ admin)
- **🎯 เกณฑ์**: แก้ตัวเลขเกณฑ์ที่กฎมาตรฐานใช้ทุกค่า (เก็บใน `data/targets.json`) ตรวจลำดับค่าก่อนบันทึก สำรองฉบับก่อนหน้าเป็น `targets.json.bak` และอัปเดต `docs/RULES_REVIEW.md` ให้เอง
- **📐 กฎ**: เพิ่มกฎของตัวเอง (เก็บใน `data/custom_rules.json`), ลองกับบันทึกตัวอย่างก่อนบันทึก, และ **ลบ/ปิดกฎมาตรฐานเก่า** เมื่อมีมาตรฐานใหม่ (ติ๊กที่ชื่อกฎ ติ๊กออกเพื่อเอากลับมา) กฎที่ปิดจะแจ้งในส่วนเฉพาะแพทย์ว่าถูกปิด
- ตัวเลขที่ไม่ใช่เกณฑ์ทางคลินิก (เช่น ต้องมีอย่างน้อย 2 ค่าถึงดูแนวโน้ม) และช่วงตรวจความเป็นไปได้ของค่า (`data/lexicon.json`) แก้ที่ไฟล์
- **✅ ตัวอย่าง**: ชุดบันทึกตัวอย่างสมมติ (`data/golden_cases.json` · ห้ามใส่ข้อมูลผู้ป่วยจริง) ก่อนบันทึกการแก้ใน 🎯/📐 ระบบรันตัวอย่างทั้งหมดและแสดงว่าผลเปลี่ยนตรงไหน ต้องกดยืนยันถ้ามีผลเปลี่ยนหรือค่าอยู่นอกช่วงที่พบทั่วไป (`data/target_ranges.json` ตั้งต้นโดยผู้พัฒนา แพทย์ตรวจและแก้ได้) ตัวอย่างที่แพทย์ติ๊ก "ผลถูกต้อง" แล้ว ถ้าการแก้ครั้งหลังทำให้ผลเปลี่ยนจะแจ้งเป็นพิเศษ นี่เป็นตัวกันพลาด (regression) ไม่ใช่การรับรองความถูกต้องทางคลินิก

## เรียนรู้ตัวย่อและสไตล์การเขียนจากบันทึกของคุณ (ในเครื่อง ไม่ส่งออก)
1. `python3 tools/learn_terms.py my_notes.txt --out learned_terms.json` อ่านบันทึกที่ตัดข้อมูลระบุตัวตนแล้ว แล้วเสนอว่าตัวย่อที่ระบบไม่รู้จัก (เช่น `BS 112`, `Crea 1.5`, คำสะกดแปลกของอาการ) น่าจะหมายถึงอะไร โดยดูจากค่าตัวเลข บรรทัดโรคที่เขียน การสะกด และดูว่าค่าที่รู้จักตัวนั้นอยู่ในบรรทัดเดียวกันแล้วหรือไม่ (เป็นสถิติเล็ก ๆ ไม่ใช่โมเดลภาษา ไม่ใช้เครือข่าย) แสดงเฉพาะคำที่พบอย่างน้อย `--min-count` บันทึก ไม่เขียนข้อความบันทึกลงผลลัพธ์
2. แพทย์เปิด `learned_terms.json` เปลี่ยน `"approve": true` เฉพาะข้อที่ถูก
3. `python3 tools/apply_terms.py learned_terms.json --notes my_notes.txt` (ทดลองก่อน) แล้วเติม `--write` เพื่อใช้จริง ระบบปฏิเสธคำที่ซ้ำกับคำเดิม และปฏิเสธทั้งชุดถ้าทำให้บันทึกตัวอย่างที่เคยอ่านถูกกลับอ่านต่างไป (เพิ่มได้ แก้ของเดิมไม่ได้) ก่อน/หลังแสดงสัดส่วนบันทึกที่อ่านครบ
- ทดสอบแล้วกับบันทึกสังเคราะห์ที่แพทย์ท่านที่สองใช้ตัวย่อต่างกัน: เดาถูกทุกตัว แต่ **ยังไม่เคยวัดกับบันทึกจริง** ผลจริงอาจต่างออกไป จึงบังคับให้แพทย์อนุมัติทุกข้อ

## ตัวช่วยเดาตัวเลข (ทดลอง · ปิดอยู่เป็นค่าตั้งต้น)
เปิดด้วย `pip install onnxruntime numpy` แล้ว `python3 -m server.app --tagger` โมเดลเล็ก (`ml_tagger/`, ~1 MB, ฝึกจากข้อมูลสังเคราะห์) จะเดาว่า **ตัวเลขที่ระบบกฎอ่านไม่ออก** เป็นพารามิเตอร์อะไร (เช่น `sugar 120` -> FBS) แล้วแสดงกล่อง "💡" ใต้ผลลัพธ์
- **ไม่ใช้ค่าที่เดาจนกว่าหมอจะกด** ปุ่ม "ใช้ FBS แทน sugar" คือการ **แก้ชื่อในช่องบันทึก** (เห็นและแก้กลับได้) แล้วระบบกฎอ่านใหม่ตามปกติ ปุ่ม "ไม่ใช่" ปิดข้อนั้น โมเดลเดาผิดได้แม้มั่นใจสูง
- ไม่เก็บบันทึก/ชื่อ/ค่าใดเลย เก็บเฉพาะตัวนับ: พารามิเตอร์ + ใช้/ไม่ใช่ + ช่วงความมั่นใจ (เห็นใน 👥 จัดการผู้ใช้ -> สถิติ) ไม่ใช่การพิสูจน์ว่าถูกจริง
- **ให้ระบบกฎจำคำใหม่ (ไม่ต้องฝึกโมเดล):** เมื่อกด "ใช้ … แทน …" และเปิดการเก็บตัวอย่าง 🧠 ไว้ จะมีคำถาม "จำคำนี้ไว้ถาวรไหม?" กด "จำไว้" = เก็บเฉพาะ (คำ, พารามิเตอร์) จากนั้นเมื่อมีหมอยืนยันซ้ำ ≥ 2 ครั้ง จะโผล่ในข้อเสนอของ ⚙️ ตั้งค่า → 🧠 เรียนรู้ตัวย่อ ให้ admin ติ๊กอนุมัติ ระบบตรวจย้อนหลังว่าไม่ทำให้ที่เคยอ่านถูกเปลี่ยนไป และตรวจว่า parser อ่านชื่อนั้นได้จริงก่อนเขียนลง `data/lexicon.json` หลังอนุมัติ **ระบบกฎอ่านคำนั้นได้เองโดยไม่ต้องพึ่ง ML**
- ไม่มี onnxruntime หรือไม่มีไฟล์โมเดล = ระบบทำงานเหมือนเดิมทุกอย่าง วัดความถูกต้องกับโน้ตจริงด้วย `ml_tagger/real_eval/eval_real.py` (ดู `ml_tagger/README.md`)

## เก็บตัวอย่างเพื่อเรียนรู้ตัวย่อ (ปุ่ม 🧠 · ปิดอยู่เป็นค่าตั้งต้น)
ระบบปกติ **ไม่เก็บบันทึกเลย** ถ้าต้องการให้เรียนรู้จากการใช้งานจริง ให้ admin เปิดที่ปุ่ม 🧠 เรียนรู้ (ควรได้รับอนุญาตจาก DPO ก่อน) จากนั้นแพทย์จะเห็นปุ่ม "บันทึกตัวอย่างนี้เพื่อปรับปรุงระบบ" ใต้ผลลัพธ์ กดแล้วระบบ **แสดงก่อนว่าจะเก็บอะไร** และเก็บเมื่อกดยืนยันเท่านั้น (รายเคส ไม่เก็บอัตโนมัติ)
- ที่เก็บ (ไฟล์ `data/learning_log.json`): เฉพาะ ค่าที่รู้จัก+ตัวเลข+ชื่อบรรทัดโรค, คำย่อที่ไม่รู้จัก+ตัวเลข+ชื่อบรรทัดโรค, คำที่สะกดใกล้อาการที่รู้จัก, ชื่อโรคย่อที่ไม่รู้จัก **ไม่เก็บข้อความบันทึก อายุ เพศ วันที่ ชื่อผู้ใช้ หรือรหัสบันทึก** ข้อความอิสระอื่น (เช่นชื่อคน) ไม่ผ่านตัวกรอง เพราะเก็บเฉพาะคำที่คล้ายอาการที่รู้จัก แถวถูกแทรกตำแหน่งสุ่มเพื่อไม่ให้เดาได้ว่าแถวไหนมาจากบันทึกเดียวกัน ไฟล์สิทธิ์ 600 จำกัด 20,000 แถว
- ใช้เรียนรู้: `python3 tools/learn_terms.py data/learning_log.json --out learned_terms.json` แล้วอนุมัติ+`tools/apply_terms.py` ตามขั้นตอนเดิม ปุ่ม "ดูข้อมูลที่เก็บไว้" และ "ล้างทั้งหมด" อยู่ในหน้าเดียวกัน

## ระยะ 1 ข้อ 1: ตรวจกฎและเกณฑ์ (แพทย์ทำ)
1. เปิด `docs/RULES_REVIEW.md` (สร้างจากกฎที่รันอยู่จริง) อ่านทีละหัวข้อ โดยเฉพาะรายการคำถามถึงแพทย์ท้ายหัวข้อที่ 1
2. เมนู **⚙️ ตั้งค่า → 🎯 เกณฑ์**: แก้ตัวเลขให้ตรงแนวทางที่ใช้ ใส่ชื่อ/ฉบับแนวทางในช่อง "อ้างอิงฉบับ" แล้วติ๊ก "ยังต้องระบุฉบับอ้างอิง" ออก ระบบเตือนถ้าค่าอยู่นอกช่วงที่พบทั่วไปและแสดงว่าผลของตัวอย่างเปลี่ยนตรงไหน
3. เมนู **⚙️ ตั้งค่า → 📐 กฎ**: ทุกกฎมาตรฐานมีปุ่ม **✏️ แก้เกณฑ์** (พาไปที่ตัวเลขของกฎนั้น) และช่องติ๊กเพื่อ **ลบ/ปิด** กฎเดิม ส่วนกฎที่เพิ่มเองแก้/ลบ/เพิ่มได้
4. เมนู **⚙️ ตั้งค่า → ✅ บันทึกตัวอย่าง**: ดูผลของแต่ละตัวอย่าง ติ๊ก "แพทย์ตรวจแล้ว ผลนี้ถูกต้อง" (ถ้าการแก้ครั้งหลังทำให้ผลเปลี่ยน ระบบแจ้งเป็นพิเศษ)
5. ถ้อยคำถึงผู้ป่วย/คำสงฆ์: แก้ที่ `data/templates.json`, `data/glossary.json`

## ระยะ 1 ข้อ 2: วัดความแม่นยำการอ่านบันทึกกับบันทึกจริง (ทำในเครื่อง ไม่ส่งออก)
1. เตรียมไฟล์บันทึกที่ **ตัดข้อมูลระบุตัวตนแล้ว** (คั่นด้วยบรรทัดว่าง) อย่างน้อยหลักร้อยฉบับ หลายสไตล์การเขียนยิ่งดี หรือให้แพทย์หลายท่านเขียนเคสสมมติ
2. `python3 tools/make_gold.py my_notes.txt --out my_gold.jsonl` ระบบแสดงว่าอ่านได้อะไร แพทย์กด Enter ถ้าถูก หรือแก้ด้วยคำสั่งสั้น ๆ (พิมพ์ `?` ดูวิธี) ทำต่อจากที่ค้างได้
3. `python3 eval/evaluate_parser.py --gold my_gold.jsonl` ได้ความแม่นยำรายค่า (อ่านครบ/ถูก/ผิด/เกิน) และจำนวนบันทึกที่อ่านถูกทั้งฉบับ รายงานแสดงเฉพาะตัวเลขและชื่อค่า ไม่พิมพ์ข้อความบันทึก
4. ส่วนที่อ่านผิดบ่อย → `tools/learn_terms.py` + `tools/apply_terms.py` หรือเพิ่มคำใน `data/lexicon.json`
- ไฟล์เฉลย (`my_gold.jsonl`) มีข้อความบันทึก ถือเป็นข้อมูลที่มาจากผู้ป่วย เก็บเฉพาะในเครื่อง ห้าม commit หรืออัปโหลด (`*.jsonl` อยู่ใน `.gitignore` แล้ว)

### อนุมัติคำใหม่ในหน้าเว็บ (ไม่ต้องพิมพ์คำสั่ง)
เมนู **⚙️ ตั้งค่า → 🧠 เรียนรู้ตัวย่อ** → ส่วน "ข้อเสนอคำใหม่": กด **สร้างข้อเสนอ** (ระบบเรียนจากข้อมูลที่เก็บไว้ในไฟล์เก็บตัวอย่าง) → ติ๊กเฉพาะข้อที่ถูก → **ใช้ข้อที่เลือก** ระบบตรวจชุดเดิม (ปฏิเสธคำที่ซ้ำ ปฏิเสธถ้าทำให้ที่เคยอ่านถูกกลับอ่านต่างไป) แล้วเพิ่มเข้า `data/lexicon.json` (สำรองเป็น `.bak`) ใช้ได้ทันที ระบบ **ไม่เพิ่มคำเอง** และเว็บเพิ่มได้เฉพาะคำที่ตัวเรียนรู้เสนอเท่านั้น (ส่งคำอื่นมาเองไม่ได้) ข้อที่ติดป้าย "ไม่แน่ใจ" ให้ตรวจเป็นพิเศษ
